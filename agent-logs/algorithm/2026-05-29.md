# Algorithm Agent Log - 2026-05-29

## Task

Audit the reported issue that varied charts may be classified as `身弱`.

## Initial Scope

- Inspect `site3/calculation-lab.js` strength logic.
- Check whether the current model overuses five-element ratio or seasonal adjustment in a way that biases toward weak output.
- Propose regression cases before changing code.

## Status

Investigation delegated to algorithm sub-agent. Results should be merged here before implementation.

## Findings

Current locations:

- Five-element point calculation: `site3/calculation-lab.js`, `countElementPoints()`.
- Day-master strength calculation: `site3/calculation-lab.js`, `analyzeDayMasterStrength()`.
- Current call site passes `dayStem.toString()`, such as `辛`, `戊`, or `庚`.

Main bug:

- `analyzeDayMasterStrength()` expects or behaves as if it has a day-master element (`木`, `火`, `土`, `金`, `水`), but receives a heavenly stem.
- The function checks the received value against the five-element array. Since values like `辛` are not in that array, the index becomes `-1`.
- This makes the support calculation collapse toward a mostly fixed `金`-based check rather than the actual day-master's peer and mother elements.
- As a result, non-metal day masters are heavily biased toward `身弱`; metal day masters also fail to correctly include earth as the mother/support element.

Observed distribution:

- Existing fixtures currently classify only as `身弱` or `従格`.
- A fixed sample matrix from 1980-2030 produced no `身強` under the current algorithm.
- When only the day-master element bug is corrected, the distribution includes `身強`, `中和`, `身弱`, `従格`, and `極強`, which strongly supports this as the immediate root cause.

Minimal next fix:

- Pass `pillars.day.element.stem` into `analyzeDayMasterStrength()` instead of `dayStem.toString()`.
- Or make `analyzeDayMasterStrength()` normalize internally: `const dayElement = STEM_ELEMENTS[dayStem] || dayStem`.
- Return explainable details with the result: `dayElement`, `motherElement`, `supportElements`, `supportPoints`, and `totalPoints`.

Regression tests to add:

- Existing fixtures should get `expected.strength.status` so the set cannot regress to all weak/follower outcomes.
- Add non-metal day-master cases with clear peer/mother support.
- Add at least one clearly strong case such as a wood day master in spring with roots/support, fire in summer, or metal in autumn.
- Add boundary cases around `0.35` and `0.65`.
- Add a distribution smoke test over a fixed date matrix requiring at least `身強`, `中和`, and `身弱` to appear.

## Implementation

- Fixed `site3/calculation-lab.js` so `analyzeDayMasterStrength()` receives the day-master element and also normalizes defensively if a stem is passed.
- Added explainable fields to `strength`: `dayElement`, `motherElement`, `supportElements`, `supportPoints`, `totalPoints`, `monthBranch`, and rounded `ratio`.
- Added `strengthStatus` expectations to embedded calculation fixtures and external fixture JSON.
- Added `spikes/calculation-libraries/scripts/strength-regression.mjs` plus `npm run test:strength`.
